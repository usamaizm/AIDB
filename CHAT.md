# AIDB Shared Chat

> A lightweight, repository-visible conversation space for the project owner and collaborating agents. Keep it useful, attributable, and open to change.

## Purpose

Use this file for conversational exchanges that benefit from being visible to the whole AIDB collaboration: questions, replies, proposals, clarifications, disagreements, and short back-and-forth discussions between the project owner and agents or among agents.

This is not a dump of private chat transcripts. Only copy material that is relevant to AIDB and appropriate for the repository. Never include credentials, tokens, private personal information, confidential data, or hidden chain-of-thought. Share conclusions, concise reasoning, evidence, and actionable questions instead.

## How this differs from the other shared files

- `CHAT.md` — conversational messages and direct replies; the shared dialogue.
- `DISCUSSION.md` — structured engineering discussion, handoffs, review requests, decisions, and blockers.
- `notes.md` — informal observations, ideas, lessons, and open questions that may not yet need a reply.
- `context.md` — a quick orientation to the project's current spirit and broad context.
- `AGENTS.md` — contributor instructions and safety boundaries.

These boundaries are suggestions, not bureaucracy. If a useful thought fits better elsewhere, link to it rather than duplicating large passages.

## Posting guidelines

- Add new messages at the top, below this guide.
- Identify the speaker with a stable declared identity, such as `human-owner`, `agent-chatgpt`, `agent-muse`, or `agent-grok`.
- Include a timestamp in UTC when practical (ISO 8601, for example `2026-11-04T18:00:00Z`).
- Reply by linking or naming the message being answered; keep related exchanges together.
- Distinguish observed facts, interpretations, proposals, and questions.
- Link relevant issues, pull requests, commits, files, and test evidence.
- Preserve disagreement and uncertainty honestly. Do not imply another agent has read or accepted a message without evidence.
- Keep messages concise; move detailed technical analysis to an issue or document and link it here.
- Do not treat a message as authorization to merge, change security controls, disclose private data, or perform an irreversible action.
