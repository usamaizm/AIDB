# AIDB Context

> A living orientation note for participating agents. This is deliberately flexible, incomplete, and open to revision. It is not a roadmap, contract, task queue, or fixed plan.

## What this is

A quick place to regain the spirit and current shape of AIDB without having to reconstruct everything from old conversations. Treat it as a helpful starting point, not an authority that overrides current source, tests, decisions, or the project owner.

AIDB is an evolving attempt to build a local-first, model-agnostic, modular substrate for agent memory, knowledge, artifacts, provenance, and collaboration. The ambition is for it to become increasingly useful and capable as it grows—including, over time, supporting carefully governed self-improvement.

## Keep the direction open

- Do not assume today's architecture, language, storage engine, formats, interfaces, or workflows are permanent.
- Do not turn suggestions in this file into mandatory commitments merely because they are written down.
- Challenge old assumptions when new evidence or a better idea appears.
- Prefer experiments, comparisons, prototypes, and reversible changes when the right direction is unclear.
- Preserve what has been learned, including failed approaches and unresolved disagreements; do not manufacture consensus.
- Keep essential trust properties—integrity, authorization, provenance, privacy, auditability, and recoverability—in view while allowing implementation and organization to evolve.

## How to orient

Start with the current repository and the task at hand. Look at relevant code, tests, recent changes, open discussions, and the shared journal. Distinguish what is implemented and verified from what is proposed, inferred, or still unknown. This note should help an agent ask better questions, not tell it what answer it must reach.

Useful companion files:
- `docs/PROJECT_CONTEXT.md` — fuller project handoff and architectural discussion to date.
- `.aidb/session-context.yml` — machine-readable orientation and pointers.
- `AGENTS.md` — contributor expectations and safety boundaries.
- `DISCUSSION.md` — cross-agent handoffs and current discussion.
- `notes.md` — informal working notes, discoveries, questions, and ideas.

## Evolving this file

Any contributor may propose edits when they materially improve orientation. Keep it concise. Remove stale assumptions, link to deeper material rather than copying it, and explain meaningful changes when context could otherwise be lost. No section or ordering is sacred.
